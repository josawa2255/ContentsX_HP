# ContentsX/BizManga HP Builder

このスキルは、HP制作時に「何から始めるか」「何を出力するか」を固定化するための実行ガイドである。

## 0. クイック起動（最初の3分）

1. 依頼を分類する: `新規ページ` / `既存改修` / `文言のみ` / `構成のみ`。
2. 対象サイトを確定する: `ContentsX` か `BizManga`。
3. 目的を1行で定義する: 例 `採用応募を増やす`, `問い合わせCVを増やす`。
4. 主要CTAを1つに絞る: 例 `問い合わせ`, `資料請求`, `無料相談`。

不明点がある場合でも、上記4項目だけは仮置きして進める。

## 1. 必須入力チェック

以下が不足していれば、先に埋める。

- ターゲット（業種・役職・温度感）
- ページ種別（TOP / サービス / 導入事例 / 採用 / 問い合わせ）
- 主要訴求（何が他社より強いか）
- 提示可能な実績数値
- 必要素材（画像・ロゴ・導線先URL）

## 2. ページ設計フロー

1. ユーザー課題を3つ定義する。
2. 各課題に対する解決価値を1対1で対応させる。
3. セクションを次の順で並べる。

- ファーストビュー（誰向け / 何が得られるか / CTA）
- 課題提示（現状の痛み）
- 解決策（サービス説明）
- 根拠（実績・事例・数値）
- 導入プロセス（不安除去）
- 最終CTA（問い合わせ導線）

4. 1セクション1メッセージを守る。
5. CTA文言は「行動が明確な動詞」で終える。

## 3. ContentsX/BizManga用の文言ルール

詳細は `references/messaging.md` を参照する。

必須ルール:

- 「AI漫画」「AI生成漫画」は使用しない。
- 「次世代ニューマンガ」「次世代ハイブリッド漫画」を使う。
- 数値実績は改変しない。
- 旧タグライン「伝えるを、再発明する。」は使用しない。
- 人間7 : AI3の制作思想を必要に応じて明記する。

## 4. 出力フォーマット（固定）

HP制作時は、最終案を必ず以下フォーマットで提出する。

```text
[目的]
[ターゲット]
[ページ種別]
[ページ構成（セクション順）]
[各セクション本文]
[主要CTAと遷移先]
[必要素材]
[実装タスク（HTML/CSS/JS単位）]
[公開前チェック]
```

## 5. 実装タスク分解ルール

- 変更箇所は `ファイル単位` で列挙する。
- フロント実装は `HTML / CSS / JS` に分ける。
- 既存導線を壊す可能性がある変更は事前に明示する。
- API依存箇所はエンドポイント名まで書く。

## 6. 公開前チェック（必須）

1. 禁止ワードが入っていないか。
2. 数値・固有名詞が正確か。
3. モバイル表示で崩れていないか。
4. CTAリンク切れがないか。
5. 既存計測（HubSpot等）を壊していないか。

## 7. 運用上の制約

- `git push` は提案しない。ユーザー判断で実行する。
- DNS/サーバー設定変更はこのスキルだけで判断しない。
- インフラ変更が絡む場合は `hirasawa_HP_infrastructure.skill` を併用する。

## 8. ページタイプ別テンプレ

ページタイプ別の標準構成は `references/page-templates.md` を使う。
